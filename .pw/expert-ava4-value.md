# 玩家价值挑刺 · 头像发型改造方案 v1 评审（2026-10-11）

**判定：SHIP WITH FIXES** —— 方向对（A+B1 确实打在用户抱怨上），但 P0 顺序错：必须先修提取器两处反转，再上 12 类几何；并补三个便宜的身份兜底件。

## 逐项裁决（评审重点 A：B1+A 够不够？）

不够。persona 数据说明身份载体排序是「HUD 玩家条 > 名牌(91-188px) > 高亮圈 > toast > 3D 头」，且 UNO **有** av 数据时仍只有 2.25/5（头 33-55px + 提取器塌缩）、mono 全景 **0/4** 棋子入画。3D 发型做得再好，也只在「棋子入画且头够大」这一窄窗口里承担身份。所以：

| 增补项 | 裁决 | 理由 |
|---|---|---|
| 名牌底色环/座位色环冗余 | **进本轮（P1-1）** | ≤44px 头上形状不可读，色环是撞款时唯一便宜兜底；persona-uno P2-4 与 persona-mono 名牌结论互相印证 |
| 交接卡头像+玩家色 | **进本轮（P1-2）** | 一行 HTML，热座身份第一现场（现状纯文字实锤） |
| 全景出画镜头修复 | **进本轮，最小版（P1-3）** | 0/4 入画让 A+B 全部投资不可见，是功能缺陷不是视觉微调；focusK 推近扩档 → 下轮 |
| B2 bot 派 av | 保留（P1-4） | 成本低，联机同样塌 |
| bombcat 不动 | 接受（P2-2） | hue 协议已有区分度，用户抱怨未指 bc，零投入正确 |

## P0（顺序即指令）

- **P0-1 修「卷发→光头」反转**：`avatar-features.js` ~L142 拯救分支与 ~L157 `pixelVetoBald` 现在都要求 `pinBald === false`，未钉扎风格（personas 等）发色簇失败时直落 `bald` 且无像素兜底。参数级改法：两处条件放宽为 `pinBald !== true`（未钉扎同样吃像素拯救/否决）；再加硬门槛 `topMass > 0.012N` 禁判 bald。验收锚点：persona-ava4-uno.cjs 选型的 personas/Jill 大卷发不再落 bald（data.json 断言）。
- **P0-2 修「金发→肤色」反转**：肤色簇选定后校验——若 skin.mean 与顶带主簇 `dist3 < 0.07`（同族＝那其实是头发），剥夺肤色资格，改由次簇重建。验收锚点：adventurer/Maria 金发场景 hair 为金系、skin ≠ #e5d6a3 同族。
- **P0-3 B1 提前为 P0 并立即做**：热座恒兜底头（G.players 无 av → syncPawnFaces 恒 undefined）是用户原话「大冒险难看出区别」的直接根因，且与提取器零依赖，可先行。monopoly.html ~L2054 / uno.html ~L1708 补 `G.players[i].av = cfg.players[i].av || hash(座位名+序号)→dcb 非抽象`；~L1674（mono）av 源改 `(NETMODE ? NDOC…av : G.players[i].av)`。
- **P0-4 顺序门禁：A1/A2/A3 必须排在 P0-1/P0-2 之后**。persona-uno 实锤：4 张发型差异极大的头像全被压成 short×3+bald×1——hairMaskMetrics 吃「非背景非肤」像素，肤色错了掩码就是垃圾，12 类是在带病管线上盖楼。修完先复跑 probe-ava-lab，再合分类与几何；brief C 的实验室门禁照旧执行。

## P1

- **P1-1 名牌底色环/座位色环**（进本轮）：把头像底色（配方 `b` 字段）或发色色相同步到名牌描边/底座色环。2D 侧一行 CSS、3D 侧一个 ring mesh，是「互相可辨」在 40px 头径下的主力，比继续加发型类便宜一个量级。
- **P1-2 交接卡头像**（进本轮）：「请把手机交给 X」卡带上座位 2D 头像+玩家色。
- **P1-3 全景最小镜头修复**（进本轮）：仅 AWAIT_ROLL/approachTurn 全景档，`rig.tgt` 向行动者角偏移（如 `tgt += normalize(actorPos−桌心) × 0.22×dist`）或 autoDist 余量 +0.8，保证行动者棋子恒在画内。「禁单页回调」钉的是视觉数值微调，0/4 入画按 bug 修不算违例；行动者推近档扩到掷骰前 → 下轮。
- **P1-4 B2 bot 派 av**（保留）：host netStartGame 写进 doc，全端一致。
- **P1-5 bun 前移抬高 / long 侧锁外倾**（随 A3 同批）：bun 现钉后顶 (0, 0.98r, −0.30r) 被颅球遮挡（persona-uno 三节），A3 落地时顺手移到 (0, 1.05r, +0.15r) 朝前上；long 侧垂锁外倾加到剪影级。同文件同批次，边际成本≈0。

## P2

- **P2-1 curly/twin 砍出本轮**：80 代表样本 **0 命中**（出现率趋零），无验证样本的几何=不可测代码。本轮 builder 级 route `curly→afro`、`twin→long`（度量类在 A1/A2 里保留记 sig），等真实命中案例出现再启用独立几何。类目多不是问题，没数据的类先上才是。
- **P2-2 bombcat 不动 = 接受**：猫脸 hue 已有区分度，本轮零投入正确。
- **P2-3 「发型像 2D」vs「互相可辨」冲突的兜底裁决**：不靠加类解决。兜底三层 = A4 连续 hairLen/hairWid（同类不同轮廓）+ P1-1 色环 + B1 hash 同房不撞派发。两玩家同选相似短发时，由发色色相+色环保可辨——这正是 persona 两报告「顶轮廓>发色相>身体色」排序的直接应用。
- **P2-4 buzz 观感偏薄**：原型自见问题，对照板加一例 40px 缩放验证后再定金值，不单独立轮。
- **P2-5 tod 房主背面裸球**：long/afro hairBack 加厚，随 A3 顺手做；tod 用户已说「做的可以」，不单独立项。

## 验收线（本轮交付，全部可测+指定取证）

1. **提取器反转清零**：复跑 `node .pw/persona-ava4-uno.cjs`，data.json 中 4 张选型头像——大卷发不判 bald（除非真秃）、无一处 `dist3(hair, skin) < 0.07` 同族。
2. **UNO 四人局两两可辨 ≥ 4/5**（基线 2.25）、**单头认回 ≥ 2.5/5**（基线 1.25）；取证复跑拼板 `persona-ava4-uno-compare.png`。
3. **热座全景可见性**：开局与每次回合切换全景档，行动者棋子 100% 在画内（投影探针断言 cy ∈ [0,760]），四子可见 ≥ 3/4（基线 0/4）；取证复跑 `persona-ava4-mono.cjs` 截图 3 位。
4. **热座无兜底头**：复跑 `persona-ava4-mono.cjs` 的 faces() 表——4 座位 style 非 null、发色两两色相差 ≥ 0.15（不再是玩家色加深的 4 顶暗帽）。
5. **实验室门禁（修正版）**：撞脸 ≤ 5、distinct ≥ 44/50、fringe/spiky/flat/bun/mohawk ≥ 4 类非零（curly/twin 不计入），guess 路径 sig 不再全同；取证 `probe-ava-lab.cjs after` + `ava-compare.png`。

## 总评（≤100 字）

方向对、顺序错。抱怨的根子一半在热座根本没有 av 数据（B1 提为 P0），一半在提取器两处「表现错」反转（卷发→秃、金发→肤）——先修上游再上 12 类。名牌色环、交接卡、出画修复便宜且必需，补进本轮；curly/twin 零命中砍出。
