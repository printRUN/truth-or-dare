# 3D 界面优化轮 · 视觉专家评审（review-3d-polish-visual）

> 评审人：视觉专家（游戏画面方向）。对象：`.pw/design-plan-3d-polish.md` v2。
> 方法：index.html 实测参数（three 内联 6131–6315 行、CSS 时钟 1632/306/3334/3336 行、DOM 牌背 276–346 行）+ 几何推演（syncCam 映射、遮挡角、FogExp2 透过率、阴影投影）+ 基线截图目检。效果图未出，以下落地效果均为参数推演，标注〔推演〕处实施后必须以截图复核。

## 总判定：【修订后通过】

方案的骨架（全屏化、有源光、桌上出卡）方向全对，但按现在的参数直接落地，会产出三个「demo 感」硬伤：
1. **题面躺在毡面上根本读不了**——0.46×0.64 的桌尺寸卡在现有相机映射下，题干字有效高度只有 6–9px（推演见 P0-3.7），婷婷「40cm 一眼读完」直接不合格。这是全方案最大的画面风险。
2. **飞卡落点与牌堆 footprint 相交**——牌堆在 (0.1, 0.1)、落点桌心 (0,0)，两张 0.46×0.64 的卡在桌面上叠压穿模（推演见 P0-3.6）。
3. **节奏空窗**——飞卡 900ms 从 t=0 起飞的话，900→2600ms 有 1.7s 死气（见 P0-3.1）。
以下逐项给参数级修订，全部修完即可达到「真 3D 桌游」及格线。

## 逐项参数级修订指令

### P0-3 抽卡/出卡 3D 化 —— 判定：修（多项）

#### 3.1 节奏时钟：必须对齐现有 2600ms 主时钟，不许另起一条
现状实测（index.html）：drawing 进入即 `focusCam(deck)` 推镜；1400ms 洗牌止（:3334）；1500ms 发牌（:3336）；抽卡者 1800ms 发布 reveal（:3392）；**所有人**在 `drawingEnterTs+2600ms` 才播揭晓（:3341，ANIM_DRAWING_MIN_MS=1632 行）；CSS 翻面 850ms（:306）。3D 路径的 revealed 等待仍由这套时钟驱动，所以：
- **飞卡不得 t=0 起飞**。修订：t≈600ms 起飞（人物走向牌堆的「伸手」拍在前 600ms），飞行 900ms，**t≈1500ms 落定——正好压在 CSS 路径的发牌拍上**。两路径节奏同构，切路径不跳戏。
- 900ms 本身不赶（弧线顶点需要 ≥0.8s 才读得出「弧」），**不许压到 800ms 以下**；但分三段：抬起 0–300ms easeOut、滑弧 300–620ms 近线性、落下 620–900ms easeIn，落定后 80ms 微弹（y 回弹 0.02）。
- 1500→2600ms 的「抽取中」窗口：桌面牌背加**呼吸微脉动**（scale 1→1.03，1.6s alternate，帧循环只写 transform——与人物呼吸同一写法，红线#4 不破）。没有这一拍，1.1s 死气会让人以为卡住了。
- 翻面定在 2600ms 时钟点，650ms，总收尾 3250ms（CSS 路径 3450ms，略紧，可接受）。
- 飞行弧线顶点：牌堆顶(y≈1.06)上方 **0.45–0.55**（绝对 y≈1.55–1.65），低于吊灯罩底(y≥2.45，见 P1-1)——卡和灯不许在画面上相碰。全程加 yaw ±180° 内的旋卡（≤180°，再多就闹）。

#### 3.2 抽卡者走位：35% 插值太浅，改为「到牌堆旁半个身位」
〔推演〕二人局 seat r=2.71，走 35% 只到 r≈1.9，屏幕上几乎看不出离座（阿凯加分 2、婷婷加分 1 都要「看见走过去」）。修订：插值比例 35%→**55%**（终点 r≈1.2，牌堆旁），walk 700–900ms easeInOut，末段 200ms shortest-arc 转身面向牌堆。8 人局远端行动者走 向牌堆新位（见 3.6）的斜线，路径穿画面中部，可读性正好。

#### 3.3 翻面：轴向、枢轴、朝向必须钉死，否则题面倒字
方案只写「绕横轴 3D 翻面 650ms」，不够，翻错方向题面就是倒的：
- **枢轴=卡的远边中点**（pivot far edge），绕本地 X 轴转 −180°：近边翘起、朝镜头方向翻过去、面朝上落在枢轴外侧——「翻给全桌看」的语义，影随卡扫过毡面（卡 castShadow=true，这是「影落地」最值钱的一帧）。落点从桌心 (0,−) 迁移一个卡长到 z≈−0.64，仍在毡内（r 2.05）。
- **不许用中心枢轴**：平贴的卡绕中心线转 180°，角部会切进毡面 0.32 单位——穿模。
- 纹理朝向：面纹（题面）绘制时**顶边朝远端**（北），翻转后题干对基础机位（+z 侧镜头）是正的。抽卡者无论坐哪侧，卡面朝北统一。
- 缓动分三段（帧循环实现）：0–55% easeIn 转到 −95°（立起），55–92% easeOut 到 −180°（拍下），92–100% settle（+2° 回弹，60–80ms）。650ms 总长比 CSS 850ms 紧一点，3D 有实体感和落牌音，可以更脆；**不许低于 550ms**，否则看不清「翻」的过程。
- 题面纹理必须在翻面开始前**一次性画完**（一次离屏绘制，静态纹理，符合红线#4；不许翻到一半才画，首帧会闪白）。

#### 3.4 题面 CanvasTexture：规格钉死（含两个必踩的坑）
- **坑一：POT**。512×680 是非 2 次幂，r128 WebGL1 下无 mipmap，平贴卡在斜视角会字迹闪烁（shimmer）。修订：**canvas 512×1024**，题面内容画在上部 680 高，下部留白。
- **坑二：encoding**。所有 CanvasTexture（题面/牌背/头像）必须 `tex.encoding = THREE.sRGBEncoding` + `tex.anisotropy = renderer.capabilities.getMaxAnisotropy()`，否则 sRGB 输出下整体发白、斜视角糊（理由见 P1-2）。
- 排版规格（对齐 DOM 揭晓卡 305–329 行的层级，512 宽 ≙ DOM 300px 宽，≈1.71 倍）：
  - 内边距 44px；徽章行：顶部居中，胶囊高 **56px**、圆角 28px、字 **30px 'ZCOOL KuaiLe'**、白字；底色 truth=`var(--truth)` #3b82f6 / dare=`var(--dare)` #f97316（与 DOM 同源）。
  - 归属行（题干上方，镜像 DOM）：头像圆 **48px** + 「「某某」抽到的题」**26px**，色 rgba(255,255,255,0.75)。
  - 题干：**44px，行高 62px**，自动换行宽 **424px**（512−88），最多 5 行，超 3 行降 44→38→34px 逐级缩排；文字区底线不越过 y=620。
  - 字体：绘制前 `document.fonts.load('30px "ZCOOL KuaiLe"')` 就绪再画，否则 canvas 落到默认字体，画风立刻穿帮。
- 该纹理在桌上的**识别**用途（类型色 + 徽章 + 前 8 字）按上规格够了；**通读**靠 3.7 的揭晓镜头，不许把纹理字号再往大堆（canvas 44px 已是桌上比例的极限）。

#### 3.5 选卡双卡：±0.62 不够，「我」会从缝里顶出来——改 ±0.78
〔推演〕竖屏后撤机位 (0, 4.25, 6.7) 下：我躯干屏幕角宽 ≈0.099 rad，双卡内缝（±0.62 时缝宽 0.78 单位）角宽 ≈0.102 rad——**缝和躯干一样宽**，躯干必然压住两卡内角，「从中间长出来」照旧（婷婷#5 不合格）。修订：
- 双卡 x=**±0.78**，z=**−0.12**（向远端让半步，构图上卡在上、我头在下，层级干净）；内缝宽 1.10 单位 ≈0.144 rad，**缝/躯干 ≈1.45 倍**，两侧各余 ~20px 竖屏净空。外缘 0.78+0.23=1.01 < 毡半径 2.05 ✓。
- 双卡几何放大到 **0.60×0.84**（牌堆卡的 1.3 倍）：竖屏屏宽占比 16%→**21%（约 81px）**，触控/raycast 热区才够半指节；纹理里「真心话/大冒险」字高 **≥110px**（512 宽 canvas），落屏 ≈17px ≥ 婷婷 16.8px 底线；图标 ≥140px。
- 躺角：**完全平贴毡面**（rotation.x=−90°），文字顶边朝远端。平贴 + 30° 仰角的纵向压缩（×0.51）靠放大几何补偿，不要翘角度——悬空翘卡没有支撑物，物理感穿帮。
- 选中反馈镜像 CSS `.choice-card.picked`（272 行 translateY−30px/scale1.12/brightness1.4）的 3D 语言：选中卡**升起 0.12 + 向镜头翘 65° + 微亮**，未选卡压暗至 opacity 0.3——两个状态必须同帧互斥，不许双卡同时浮。

#### 3.6 〔新发现〕牌堆必须挪位，否则飞卡落点穿模
现状牌堆 (0.1, 1.01, 0.1)（6175 行），方案落卡点桌心 (0,0)：两卡 footprint（各 0.46×0.64）**在 x、z 双向重叠**，抽出的卡会插进牌堆里。修订：牌堆移至 **(1.12, y, 0.60)**（r≈1.27，毡内）：与桌心揭晓卡（x −0.23..0.23）不相交，与右侧选卡（z −0.44..0.20 vs 牌堆 0.28..0.92）不相交。副产品：飞卡行程从 0.14 单位变成 **≈1.3 单位的真弧线**，900ms 的飞行动作终于有得飞；牌堆偏置一角也是真牌桌的摆法。

#### 3.7 〔方案缺口·最高优先〕揭晓必须给专属近景机位，否则题面读不了
〔推演〕题面卡平贴毡面（0.46×0.64，屏高占比 ~10%）、字 44px/680 高 → 落屏 **6–9px**，40cm 外不可读（婷婷硬标准 5 不合格）；现有 syncCam 映射（6257 行：y=3.75+(rx−19)×0.03、z=5.4+(−56−z)×0.035）的可达位姿（≈dist 4.7、仰角 38°）算到极限也只有 ~10px。方案对揭晓镜头只字未提，这是「参数堆的 demo」和「导演过的桌游」的分界线。修订（视觉要求，实现路径归 eng）：
- 翻面起始（t=2600ms）同步推近：**落幅=仰角 50–55°、镜头到卡面距离 ≤3.2 单位**，卡面屏高占比 **≥30%**（桌面端 ≥270px / 竖屏 ≥250px），题干落屏 **≥16px**；
- 构图：抽卡人头肩必须在画面上三分之一（阿凯揭晓连续性「题面与抽卡人的脸同框」），机位侧偏（如 (1.6, 2.6, 3.0) lookAt 卡面）避免卡正后方顶着人；
- 推镜时长 1.0–1.2s 与翻面同拍；交接阶段拉回基础位。
- 约束说明给 eng：现 syncCam 是 Cam.cur 的线性从动（改 CSS rx/z 会把 DOM HUD 一起扭歪），需要为 drawing/reveal 开「三空间位姿叠加」通道；名牌投影用同一 camera 对象，自动保持贴合，无额外成本。

### P1-1 灯光 —— 判定：修（参数补钉）
- **吊灯可见体**：灯罩圆锥顶 r0.10/底 r0.30、高 0.26，罩底 y=**2.49**；〔推演〕罩底必须 ≥2.45——基础机位下镜头到对面玩家头顶的视线在桌心上方 y≈2.14 过，灯罩低了会正好骑在对面玩家头上。灯泡 r0.07 MeshBasicMaterial 0xffe9c4（自亮，toneMapped，不会炸）；灯罩内壁 emissive 0xffd9a8 强度 0.9；吊线 r0.008 圆柱伸到 y=6 出画。〔推演〕基础机位灯在画面上方 12–20% 处，可能贴到标题/房间号行——验收时 A/B 截图，若相碰，lookAt y 0.55→0.85 微调（灯下移出 HUD 区），**不许降低灯位来躲**。
- **点光**：0xffe2b8→**0xffd9a8（≈3000–3200K 暖）**，强度 1.15→**1.25**，distance 20→**9**，位置 (0, 4.4, 0)→**(0, 2.58, 0)**（罩内）。distance 9 让地板在 r≈3 外衰减到 <50%，光池边缘自然成形——「亮而无源」变「一盏灯照亮一张桌」。锥角：用 Point+距离衰减成池，不用 SpotLight（罩底高 1.6 单位要盖住 r2.05 的毡面需半角 ≥52°，宽锥没「光池」感）；若坚持 Spot：half-angle 55°、penumbra 0.5，但**必须**继续由 Directional 承担阴影。
- **阴影方向（穿帮红线）**：阴影 DirectionalLight 必须与「灯在桌心正上方」自洽，**位置 (−1.7, 6.0, 1.3)、target(0,0,0)**（偏垂直 ~19°）：影子短（人高 1.53 → 影长 ~0.55）投向 **+x/−z（右后）**，永不投向镜头、永不拖到选卡区。**不许**沿用现补光方向 (−4,3,6)（~40° 侧光，影子指向与吊灯矛盾，阿凯「用手指画出光源在哪」当场不及格——两个光源互相拆台）。影长 0.55 在 60px 人物旁仍可读；再陡（>25°）影子拖太长就假。
- **mapSize 1024**：shadow camera ortho **±3.6**（8 人座位 r2.71+身位 0.35 全包），near 2 / far 12，bias −0.0002 + normalBias 0.02。〔推演〕1024/7.2=142 texel/单位，我的影子在屏上 ~1:1.2 texel:px，PCFSoft 下够用；**只有** A/B 截图出现影子爬行才升 2048（升不升是 eng 帧预算的事，视觉只认截图）。
- 受影面：floor+felt+table top receiveShadow；人物 torso/chest/head/hair/stool、桌沿、牌堆、**飞行/翻转中的卡** castShadow。
- **吊灯摆动**（阿凯加分 1 的廉价实现）：只摆灯罩 mesh，±1.2°、周期 3.5–4s；**光源 PointLight 位置逐帧不动**（动光=逐帧动整条光路，得不偿失），1.2° 失配肉眼不可见。

### P1-2 ACES+sRGB —— 判定：修（重配值 + 拆步骤）
- **紫毡 0x4c2a8f→0x3d2276 会不会更闷/更脏**：〔推演〕两个区域两种答案：暗缘在 ACES 下饱和度收缩、更闷（偏藏蓝）；亮心被暖键光乘色（76,42,143 × 暖光 ≈ (76,36,94)）失蓝变灰紫——「脏」主要发生在光池中心。**对策不是把 albedo 一竿子捅到 0x3d2276**（ACES 降亮度 + 暖光去饱和 + 再压 albedo = 三重叠加必发闷），而是拆步 A/B：第一步**保持 0x4c2a8f** 只上 ACES+新灯；若光池仍「霓虹」，第二步降到 **0x462688**；0x3d2276 留作最后手段。噪声纹理保留但**对比 ±4% 亮度以内**（256×256 POT、RepeatWrapping、repeat 5×5，作 map 乘色保色相）——布纹要「摸得出来」而不是「看得出来」。
- **三灯重配建议值**（exposure 1.05 前提）：
  - 环境光 Ambient(0x8890c0, 0.9) → **HemisphereLight(0x7078b8 天, 0x2a1840 地, 0.7)**（给毡面顶部冷洗、地板更暗，「房间」感的主要来源；eng 若坚持 Ambient：0x767eb8×0.6）；
  - 暖点光按 P1-1（0xffd9a8, 1.25, dist 9, y2.58）；
  - 阴影平行光 (0xffedd0, 0.8)（方向见 P1-1）；
  - 冷补光 (0x88aaff, 0.32)→**(0x88aaff, 0.24)**——**不许砍到 0**：它从镜头左后打亮「我」的背脊，是剪影的缘光（wiki #tp-back 逆光剪影语言的 3D 化），砍掉我就成贴在亮毡上的黑洞（阿凯#4「黑蛋」复发）。
  - 〔推演〕毡心总照度 ≈2.4–2.6（现 ≈2.15），ACES 后光池亮、边缘沉，暗部比现在多吞 10–15%——层级正是要的。
- **头像脸盘 MeshBasicMaterial 会不会过曝**：不会因 tone mapping 过曝（r128 Basic 默认 toneMapped=true，中间调只被轻压）；**真正的坑是编码双跳**——CanvasTexture 默认 LinearEncoding，sRGB 输出会把头像**提亮发灰**（0.5→0.73 那种洗白）。修法即 3.4 的 encoding=sRGBEncoding， Face 保持 Basic（自亮保证暗房间里头像可读，这是婷婷「认得出人」的保底，不改材质）。

### P1-3 牌堆像牌 / 牌背一致性 —— 判定：修（纹理内容钉死）
DOM 牌背语言（279/280/312 行）：`linear-gradient(135deg, #8b5cf6, #f472b6)` + 外白边 2px rgba(255,255,255,0.3) + **内虚线框 inset 7px（宽 5.4%、高 4.1%）、1.5px dashed rgba(255,255,255,0.35)** + 圆角。3D 牌背纹理必须四件全带：
- 256×512 POT canvas：全幅渐变（135° 对角），白边按比例画（x 3.5px、y 5px 处 2px 等效），虚线内框 rect（x 14 / y 21 内缩），圆角在 box 几何上本来没有——由边框直角替代可接受（桌上小尺寸看不出）。
- 顶面材质 **MeshStandardMaterial + map**（受光一致），侧面纯色 0x7c3aed；**不许用 Basic**（光池里会像贴纸浮在毡上）。
- 5 张薄片：厚 **0.012**（总叠高 0.06 ≈ 现 0.05–0.10），每张 y 旋转 **±0.06 rad 随机**、x/z 抖动 **±0.008**——乱度对齐 DOM 桌面牌堆的 −6°/1°/8°（780–782 行），过了就乱。
- 抽取中桌心牌背、飞卡、牌堆顶**共用同一张纹理**——一个语言，三处出现，一致性白拿。

### P1-4 竖屏后撤 —— 判定：修订后可过（后撤量够了，卡距不够）
〔推演〕z+1.3/y+0.5 → 机位 (0,4.25,6.7)：我全身屏高占比 **22–26%**（脚 44.7°/头顶 34.3° 仰角差 10.4° ÷ 46° fov），已满足 ≤35% 目标，甚至有余量——**后撤量本身通过**。但如 3.5 所述，±0.62 的双卡缝和躯干同宽，占比达标也照样穿帮。故：
- 维持 z+1.3/y+0.5 实施基线；
- 双卡改 ±0.78（3.5）后，「我」正坐缝中、两侧 ~20px 净空，构图成立；
- **实施时仍必须截图标定**（390×844 A/B）：验收线=我全身屏高 ≤35%、躯干与任一选卡内缘不重叠、选卡落屏宽 ≥75px。推演不是效果图，以截图为准。

### P0-2 雾密度 0.05 —— 判定：修（0.042，附安全区间）
〔推演〕FogExp2 因子 1−exp(−(ρd)²)：
- 对面人物：桌面机位距离 ≈8.5 → ρ0.05 时 **16% 雾洗**（可接受）；竖屏后撤后 ≈10.3 → **23%，开始发奶**。
- 安全区间：**ρ=0.042（0.035–0.046）**。上限约束=竖屏远端人物透过率 ≥80%，即 ρ ≤ 0.046；下限 0.035 以下地板远缘遮不住。
- 配套：地板 r10→**48**（ρ0.042 时 d≈50 处雾化 98.8%，硬边消失；r40 只有 95%，留 5% 阶梯）；**fog 颜色必须= 0x0a0a1a（--bg）**——canvas 是 alpha 透明底，雾只能渐变到雾色而不是透明，色号不取页面底色就会在星空上浮出一块异色圆盘。
- 名牌是 DOM 不吃雾，远端名牌保持锐利——正好，身份识别交给名牌+自亮脸盘，构图交给雾。

## 画面语法总检（wiki/design/third-person-table.md 那句话还成立吗）
原句「暗下去的桌面、亮着的我、浮在桌上的题、对面一圈脸」是为 CSS 路径写的。新灯光下按 3D 语义**转译后依然成立**，且必须按这个转译验收：
- 「暗桌面」→「**暗房间 + 一池亮桌**」：地板近黑（0x110a24+Hemi 地色），光池只圈住毡面——比原来更贴骗子酒馆；
- 「亮的我」→「**近景剪影 + 缘光**」：我背对灯成逆光剪影，冷补光 0.24 勾出肩头轮廓（正是 #tp-back 的语言），脸盘自亮兜底可读；
- 「浮在桌上的题」→「**躺在毡心的题**」+ 揭晓近景（3.7）把它顶到可读尺寸；
- 「对面一圈脸」→ 自亮头像盘不受光衰减，恒为画面最亮 identity 层。
明度硬序（验收用截图直方图核）：**UI 玻璃卡 > 头像脸盘 > 光池毡心 > 人物体色 > 地板**。任何一档颠倒（比如毡心压过脸盘、或人物黑过地板）即打回。

## 我坚持的底线（不可再让步）
1. **题面可读性**：最终揭晓 framing 下题干落屏 ≥16px（竖屏）/≥15px（桌面），以截图实测为准。做不到就把 3.7 的近景机位做出来，不许用「纹理字号再放大」糊弄，也不许退回 DOM 大卡盖人。
2. **单一光源叙事**：可见吊灯=唯一光源叙事，阴影 Directional 与吊灯方向偏差 ≤20°、永不投向镜头；cool fill 只作缘光不得成为第二「光源感」。
3. **节奏挂在现有 2600ms 时钟上**：飞卡 600ms 起飞/1500ms 落定/2600ms 翻面，CSS 与 3D 两路径节拍同构；空窗不得 >1.2s。
4. **不穿模**：牌堆移位 (1.12, 0.60)；飞卡落点、选卡双卡、揭晓卡、牌堆四者 footprint 两两不相交；翻面必须边枢轴。
5. **纹理三件套**：POT 尺寸 + sRGBEncoding + anisotropy，所有 CanvasTexture 无例外；题面一次性离屏绘制，逐帧只写 transform。
6. **明度硬序**：脸盘 > 毡心 > 体色 > 地板，截图直方图验证；cool fill ≥0.2 保「我」的剪影轮廓。
