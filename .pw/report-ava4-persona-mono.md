# 玩家模拟走查报告：4 人本地热座 3D 头像/棋子可区分性（阿泽/老白/婷婷/小美）

- 复跑：`node .pw/persona-ava4-mono.cjs`（端口 9081，`monopoly.html?inspect=1` 真机路径，全真实 UI 点击：高级选项→加座→改名→开始热座→交接卡→掷骰→买地；`__mono` 仅只读取证）
- 证据：`.pw/shots/persona-ava4-mono-*.png`（15 张）；视角 1280×800、DPR=1

## 结论（先行）

**可区分性：2 / 5 分。** 身体颜色（青/粉/紫/绿）在对局中基本能分清，但「头像」维度为零——4 个 3D 头完全同几何同脸，只差一顶「身体色加深」的帽；且默认镜头下经常有 2/4 棋子根本不在画面里，玩家实际靠名牌和 2D HUD 文字认人，3D 头像没有承担身份职能。

### 三条最重要发现

1. **热座兜底头实锤，特征全空。** `faces()` 返回 `fb:0..3`，`style/glasses/beard` 全 null，发色 `#1f616c / #72214b / #392071 / #1f6d3c` = 玩家色按 `fallbackHair()` 深化（L≈0.22-0.32，四顶帽全是暗色系，缩小后彼此难分）。代码锚点：`startGame`（monopoly.html ~2054）构建 G.players 无 `av` 字段；`syncPawnFaces`（~1674）头 av 源 `NETMODE && NDOC.players[i].av` 热座恒空 → `AV3.buildAvatarHead(0.1, colorIdx, undefined, fallbackHair)` 同一个头×4。
2. **默认全景镜头下棋子成批出画。** 开局 4 子聚 GO，投影 cy≈1093-1107（视口仅 800）→ AWAIT_ROLL 全景里 **0/4 棋子可见**（截图 3：只见骰盘和「阿泽 的回合」按钮）。中盘/收尾也只 2/4 可见（截图 10：阿泽在监狱、老白在右侧，婷婷半出画、小美完全出画）。`approachTurn` 全景档 `rig.tgt` 恒桌心 (0,0.3,0)、dist 7.66、elev 42°，近角棋子必然落出下缘——「这步是谁的」在 3D 层一半时间是缺失的。
3. **头球尺寸决定了「五官路线」走不通，而名牌是唯一稳定身份载体。** 量测（1280×800 全景档）：头球直径 **21-44px**（随距 5.1-9.8）、全身高 **37-56px**（俯角下被压扁）、名牌宽 **91-188px**。≤25px 的头上画眼镜/胡子/嘴形纯属浪费像素；名牌（色点+名字白 pill）和 HUD 玩家条（active 高亮描边）才是玩家真正在看的。另外：设置屏右侧就摆着整套 DiceBear 2D 头像定制器（31 种风格，联机房用），热座座位行（色点+名字+🤖）却没有接入——基础设施都在，只差线。

### 参数级建议（可执行）

- **特征优先级（俯视 42° 下实测可读性）**：**发型顶轮廓 > 发色色相 > 身体色 ≫ 眼镜/胡子/五官**。热座自动派头像后，3D 头要放大的是「顶轮廓差异」（afro/丸子/平头/尖毛的剪影）和发色色相分离（别再用玩家色加深——4 个暗帽没法看），眼镜、嘴形在 25px 头径下不可读，低优先。
- **给每个热座座位自动派 2D 头像：必要但不充分。** 头像→3D 头特征能补齐「头像维度」，但补不了「出画」和「太小」：必须配套 (a) 全景档把 `tgt` 向行动者角偏移或抬 `autoDist` 余量，保证行动者棋子恒在画内；(b) 行动者棋子推近档（focusK）覆盖到掷骰前，而不是只在走位时。
- **交接卡是热座身份的第一现场，却只有纯文字。** 「请把手机交给 阿泽」无色点无头像（截图 2）；把座位 2D 头像+玩家色带上，成本一行 HTML，收益直接（传机时不用读屏找色）。
- 名牌保留并可在走位推近时加大一号——它是当前唯一在 3D 场内稳定可读的身份元素（监狱铁笼是唯一「结构性可辨」位置，截图 10 阿泽）。
