## 二、换屏转场帧序列分析（本次最重要的评审点）

### 方法
- rAF 逐帧采样（页面内）：两面 `.screen.entering/.leaving` 各自的 rotateY（从 matrix3d 线性部分 `atan2(m8,m0)` 精确解出）、投影框、opacity、面宽、`--tx-r`、`#world3d` transform；
- CDP screencast 真实时间轴连拍 → 按动画时刻挑 0/150/300/450/600/750ms 存 `sim-cube-<段>-t*.jpg`；
- 页面内哨兵在 |θ入|∈32°~62° 时同帧 `getAnimations().pause()` 冻结 → 无损 PNG 中段定帧 `sim-cube-<段>-mid.png`（冻结前把两面 1s/0.9s 的清理定时器改挂 6s，解冻后动画播完再手工收尾，保证帧序列不被定帧污染）。

### 缓动与运镜评价（阿凯锐评）
- **缓动本身是 Apple 味的**：cubic-bezier(0.4,0,0.2,1) 配 90°，实测角度-时间曲线 = 前 100ms 只走 0.4°（蓄势）→ 中段 235–467ms 冲了 ~48°（峰值 ~210°/s）→ 后 300ms 长尾收停。快慢分布对「转身」是对的，没有匀速转门的廉价感。
- **但 join→lobby 这段（每个玩家每局必经的第一次换屏）观众只看到一半**：起转要等加载层揭幕（实测延迟 ~3s），起转后前 ~250ms 画面仍被半透明加载层盖着（t150 帧几乎全黑、t300 帧中还有「落座中」鬼影卡），600ms 后角度已小于 7° 不可感知——**800ms 预算真正可见的只有中间 ~350ms**。揭幕节奏和转身节奏是两条timer各跑各的。
- **镜头与转身的叠加：不打架，但 join 段「镜头先跑了」**。lobby→game / game→result 里镜头推进（wz −48 / −84，rx 5→6.3 / 10.7）与转身同台，dolly 在 z 轴、转身在 Y 轴，读起来是「走进去 + 墙转开」，浑然一体，这是好设计。唯独 join→lobby 的 Cam.enter 在 renderScreen 时立即起跑，推进段（540ms）整个烧在加载层后面，观众看到的转身只剩镜头归位的尾巴。
- **「刚体」成立，但「材质」露怯**：定帧看，lobby→game / game→lobby 的中缝两面几乎焊住，读得出一个墙角；game→result 的入屏面只有一块 320px 窄面板，转角读作「一堵墙 + 一扇窄门」，体量不对称；join→lobby 的两面大多是透明玻璃（内容盒之外无底色），中缝处两面都「看不见」，刚体感靠同步运动撑着。**和苹果官网的 section 过渡比：苹果的入场内容永远先给一块实底，转角永远不透；这里的几何做到了，材质没跟上。**
- 另：转身时标题/房间 chip/表情浮标不随世界转（在 #world3d 外）——chrome 静止、世界转动，这个分层本身 Apple 也常用（导航不动内容动），可以保留，但在玻璃缝+鬼影叠加时会让「空间感」打折。

## 四、痛点 Top 5（按严重度）

### 1. join→lobby 换屏：转身的前 1/3 被加载层盖住 + 揭幕鬼影叠在转角上
- **现象**：点「加入游戏」后 ~3s 才起转（等待层），起转后 t150 帧画面仍近全黑、t300 帧中央还有半透明「落座中」卡片鬼影，600ms 时角度已小于 7°——800ms 转身真正可见的只有 ~350ms。
- **复现**：任何一次建房/加入（每个玩家每局必经）；`sim-cube-join-lobby-t150/t300.jpg`、`sim-cube-join-lobby-mid.png`（鬼影就在两面中缝上）。
- **苹果官网会怎么做**：揭幕本身就是过场的第一节——overlay 用 200ms 快速揭走（scale 1.06→1 + blur 8→0），揭幕完成事件直接触发转身起跑；两者是同一条时间轴上的两拍，不会互相盖。

### 2. 揭晓卡的「空窗拍」：镀铬先到、题面迟到（1280 下 ≥1.2s）
- **现象**：翻面完成后类型徽章、惊喜卡角标、押注面板、底部动作条全部就位，题面区空白 0.6s+（1440 实测 3.15s 帧全空、3.9s 才有全文；1280 复核在 revealed 状态后 1.2s `#punishment-text` 宽度仍为 0）。惊喜卡触发时「🎁 惊喜卡·彩带风暴」角标还直接压在「💬 真心话」徽章上。
- **复现**：任何一次抽卡；`sim-desktop-draw-5-flip.png`、`sim-desktop-1280-revealed.png`。
- **苹果官网会怎么做**：内容永远先于装饰——先打字机，第一个字符落地再弹类型徽章，题面完整后 120ms 才上惊喜角标和彩带；打字机以 `turn.ts` 为统一时钟，状态迟到 ≤300ms 就吃掉，不让观众对着空卡等。

### 3. 1440 大厅两栏：右列 80% 空场，下半屏全是空的
- **现象**：内容列 1180px（左 555/右 599），4 人局右列只有顶部 ~150px 一行头像，其下 ~450px 纯背景；左列内容止于 y≈485，y620 以下整屏空场，「开始游戏」孤零零悬在中间。
- **复现**：1440×900 四人大厅；`sim-desktop-lobby-4p.png`。
- **苹果官网会怎么做**：要么把右列做成真正的工作面板（玩家名单 + 房间设置摘要 + 大开始按钮 = 主持控制台），要么承认内容就一列宽，把余白交给背景——「为分栏而分栏」是布局的大忌。

### 4. 「第 N 轮」chip 语义错误：显示的是轮转位置，不是局内轮数
- **现象**：开局第一回合（没人抽过牌）顶部 chips 显示「第 4 轮」（因为当前持麦人是第 4 个加入的婷婷）；玩家和主持人都会误读成「已经打到第 4 轮」。代码证实：`index.html:2368`，轮流制下渲染 `(turnIndex % players.length) + 1`。
- **复现**：任何一局的第一回合看顶部 chips；`sim-desktop-game.png`（第 2 轮）、`sim-desktop-draw-1-fly.png`（第 4 轮）。
- **苹果官网会怎么做**：标签不许撒谎——要么改叫「第 N 手」（轮转位置），要么显示真实进度「轮数 X/Y」（`S.stats.rounds`/`roundLimit`），一个词的差别。

### 5. 颁奖台没有「台」：结算屏的仪式感配不上前面 6 秒的高光
- **现象**：冠军排在左侧而非居中，三甲同一基线无高度差，奖牌是小圆片；四枚奖章 chips 与普通 chips 同款式平铺，冠军奖没有任何特殊待遇；一次性彩带在截图时刻已散尽。
- **复现**：打满轮数或 🏁 结算；`sim-desktop-result.png`。
- **苹果官网会怎么做**：颁奖台就是要有台——2-1-3 台阶布局、冠军居中升高 + 金环呼吸、金色纸屑只落在冠军列、奖章 chips 逐个 80ms stagger 弹入且冠军 chip 金底；仪式感=空间+时间两个维度的偏心。

**落选但记录在案**：1280 工具栏第二行贴折线 + toast 压按钮（`sim-desktop-1280-lobby.png`）；转角玻璃缝的透明感（见第二节）；禁用态选卡只压透明度、无「还没轮到你」的就地标注；视差幅度弱到近乎不存在。

## 五、升级方案愿望 Top 5（具体做法，不说空话)

1. **揭幕与转身同拍（一次改 `hideLoading`/`queueSceneEnter` 的握手）**：把加载层退场压成 200ms 的「揭幕」动效（`opacity 1→0` + `scale 1.06→1` + `blur 8px→0`），在揭幕完成的同一帧再 `armCube + playSceneEnter`；或者反向——保持现有时序，但把 `scene-in` 的 opacity 坐实点从 22% 提前，并给 `.entering` 加一个 0–250ms 的「自身揭幕」亮度爬升，让被盖住的开头不再是黑帧。验收：重跑本脚本，`sim-cube-join-lobby-t150.jpg` 应能看清两面角度。
2. **给转角焊上实体背板**：`.screen.entering/.leaving` 各挂一个 `::before`（`position:absolute; inset:0; pointer-events:none; z-index:-1`），深色渐变底 + 左/右 1px 高光棱线，opacity 跟随动画（in: 0→1@22%，out: 1→0@55%后），动画结束随 class 一起消失——常态仍 `transform:none`、不碰 preserve-3d 红线。入屏面内容再窄（结算 320px）也有整面墙的体量，转角永远不透。
3. **揭晓节奏「内容先于镀铬」**：`playReveal` 里把 type-badge/惊喜角标/彩带的出场推迟到打字机首字符落地（type-badge）与打字完成 +120ms（惊喜+彩带）；惊喜角标与类型徽章改同一行 flex（gap 6px）或对角分布，消除重叠；打字机启动加 `turn.ts` 补偿（迟到 ≤300ms 吃掉、>300ms 才顺延），1280 复核的「+1.2s 仍空」直接消失。
4. **1440 大厅右列改成「主持控制台」**：右列改为一张卡：顶部玩家名单（头像+名字+👑/🎤/⏭ 行式列表，hover 可点名）、中部房间设置摘要（玩法/尺度/计分/轮数，主持可直接点改）、底部全宽「开始游戏 🚀」大按钮（从左列挪过来，主持人的手永远在右下角）；左列只留邀请与题库。4 人局右列填充率从 ~20% 到 ~85%，且主持操作距离缩短一半。
5. **颁奖台做「台」+ 进度诚实**：podium 改三级台阶（grid 三列，2-1-3 排列，1 位高 72px、2 位 40px、3 位 24px 的台面 + 冠军金环呼吸 + 冠军列独享金色纸屑）；奖章 chips stagger 弹入（80ms 间隔、spring 缓动）+ 冠军 chip 金底描边；`stat-turn` 在计分开启时直接改渲染「🔄 X / Y 轮」（rounds/roundLimit），轮流位置信息挪进 turn-info 文案里（「轮到小雨 · 第 2 手」）。
